2. How Shapely built them (from Shapely's repository at tag 2.2.0, commit
   229c71f7128713b37201f3c77336d32b52467454)

   - .github/workflows/release.yml: GEOS_VERSION "3.14.1"; runner windows-2025; MSVC toolset
     14.44 (TheMrMilchmann/setup-msvc-dev@v4, arch x64); cibuildwheel v4.2.1 runs
     ci\install_geos.cmd before the build.
   - ci/install_geos.cmd: downloads http://download.osgeo.org/geos/geos-3.14.1.tar.bz2 and
     builds it unmodified (no patches) with CMake and Ninja:
     -D CMAKE_BUILD_TYPE=Release -D BUILD_SHARED_LIBS=ON -D BUILD_TESTING=OFF, then installs.
   - The wheel was then repaired with delvewheel 1.13.1 (recorded in the wheel's
     shapely-2.2.0.dist-info/DELVEWHEEL: "repair --add-path D:\a\_temp\geos-3.14.1\bin"). delvewheel
     copies the DLLs into shapely.libs/, renames them with a hash suffix and rewrites the import
     entries that refer to them; GEOS's code isn't changed.
   - The public run: Shapely's "Build and publish" workflow, run 37597567800 (2026-10-07,
     https://github.com/shapely/shapely/actions/runs/37597567800).

4. Replacing GEOS with your own build

   The DLLs are loaded at run time: shapely\lib.cp314-win_amd64.pyd and
   shapely\_geometry_helpers.cp314-win_amd64.pyd import
   geos_c-6dd9fd915eef8a7928285416bef1e666.dll, which imports
   geos-bf067cd6ff74ee0ad5f3ff52c7ef08c9.dll. To use a modified, interface-compatible GEOS:
   build it for Windows x64 as in section 2 (BUILD_SHARED_LIBS=ON); build Shapely 2.2.0 from its
   source (sdist shapely-2.2.0.tar.gz, SHA-256
   e8865e553d874a1ec4a032057ea81fca9def37b188cd8fb550af3b3480b3f88c) against it and repair the
   wheel with delvewheel as in release.yml; then replace runtime/site-packages/shapely/ and
   runtime/site-packages/shapely.libs/ with the new wheel's. (Replacing only the DLLs also
   works if the new files take the names above and geos_c's import of the GEOS C++ DLL is
   renamed to match, which is what delvewheel does.)
